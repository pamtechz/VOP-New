# Voice of Prophecy — Firebase/Android and offline-lesson cutover

Target repository: `Pamtech-Zambia/VOP-New` only. Firebase project: `voiceofprophecy`. Android application ID: `com.sda.vop`. **This file is a release runbook, not a claim that remote Firebase setup or production cutover has occurred.**

## 1. Dependencies and skills

The inspected VOP `package.json` contained no Supabase dependency; its previous runtime used browser-local demonstration data. For any separate old client actually containing Supabase, inspect `npm ls @supabase/supabase-js @supabase/ssr @supabase/auth-helpers-react @supabase/auth-helpers-nextjs` and remove only installed entries using `npm uninstall @supabase/supabase-js @supabase/ssr @supabase/auth-helpers-react @supabase/auth-helpers-nextjs`. Remove `supabase` developer CLI only when it is solely used for the retired backend (`npm uninstall -D supabase`). Never migrate another repository's Supabase project or credentials by inference.

VOP PR installs and locks `firebase@12.19.0` and `@capacitor-firebase/authentication@8.5.2`, verified with `npm install --save-exact ...`; `package-lock.json` is committed. On a developer machine run `npx skills add firebase/agent-skills --agent=codex` and read the Firebase Auth and Firestore skills when changing these modules. The requested skills installer could not complete in the assistant's isolated network runtime; corresponding official public skill guidance was read for implementation.

## 2. Register actual apps in the EXISTING Firebase project

Open Firebase Console → project **voiceofprophecy** → Project settings → Your apps. Register an **Android** app with application ID **com.sda.vop**, NOT the older `com.rvc.vopapp`. Add SHA-1 fingerprints for the debug and the actual distribution/release signing certificate; follow Firebase's Google sign-in guidance for other required fingerprints. Download `google-services.json` for this exact Android app and place it at `android/app/google-services.json` in a controlled local checkout. Never use a JSON file from an unrelated project or package. If the project already has an app registered with this precise ID, verify and reuse it instead of creating duplicates.

Also register a **Web app** in the SAME project (required for Firebase JS Web SDK). Copy its *public Web configuration* (`apiKey`, `authDomain`, `projectId`, `appId`) into `.env.local` following `.env.example`. The project guard in `src/lib/firebase.ts` rejects any `projectId` other than `voiceofprophecy`. These Web config values are client-visible identifiers, **not** Firebase Admin service-account secrets. Never place a service-account JSON, private key, or Admin SDK credential inside the APK or `VITE_*` environment variables.

In Firebase Console → Authentication → Sign-in method, enable **Email/Password** and **Google** for `voiceofprophecy`; set the support email and check authorized domains for any deployed Web hostname. The native Android account picker uses `@capacitor-firebase/authentication` with `skipNativeAuth: true`, then signs the returned Google ID token into Firebase Web Auth. Embedded OAuth in an Android WebView is not the substitute for the native picker.

## 3. Firebase security, data layout and permissions

`firebase.json` and `.firebaserc` are scoped to project `voiceofprophecy`. Review `firestore.rules` and run Firebase Emulator Suite tests (allowed owner get/list/create, rejected unauthenticated/cross-user, malformed submissions, overwrite/delete, and unpermitted paths). Verify Firestore database edition/region, billing and rate limits before any production deployment. After user approval and emulator proof, deploy **rules only** with `firebase deploy --project voiceofprophecy --only firestore:rules`; do not overwrite another project's settings. There are no remote Firebase management credentials/console actions available in the current ChatGPT GitHub connection, so Android app registration, provider enablement, and rules deployment require a real project administrator.

Firestore paths: `users/{firebaseAuthUid}/progress/{randomSubmissionId}`. Current rules only authorize the signed-in owner to append validated `practice_unverified` records; profile editing, staff roles, official grading, approvals and credential issuance are deliberately NOT authorized. A client-selected UID or role is never proof of identity. Avoid client-side certification even if a score looks correct.

## 4. Offline lesson snapshot pipeline

Provide the approved complete `content/lessons.master.json` following the schema in `scripts/generate-snapshots.js` (80 language codes × 26 consistent IDs = 2,080 unique entries, 20 nonempty ordered pages and 5 valid quiz questions per entry). No complete master was found in the inspected repository; the current `src/data/initialData.ts` contains partial demonstration material and must NOT be duplicated 80 times as invented translations.

Run `node scripts/generate-snapshots.js` with the real master. The generator must fail closed if any pair, page, or quiz is missing, and writes minified `public/lessons/{lang}/{lessonId}.json`. Review the generated manifest and sample translations before release. Once this output exists and is approved, add `"prebuild": "node scripts/generate-snapshots.js"` to package scripts so CI always regenerates content before `tsc -b && vite build`; run `npx cap sync android` after the build. The generator reads a local master during build, not Firestore on the handset. If source content currently lives in a development database, export it in an authorized build-only job, validate and pin that export before packaging. Bundle contents are accessible to APK users; do not include unpublished manuscripts or private answer keys if secrecy matters.

`src/pages/LessonViewer.tsx` loads Vite's bundled JSON using `import.meta.env.BASE_URL`, validates lesson content and holds five answers in React state. It writes ONE append-only practice record when the signed-in learner presses Submit, labels offline pending writes as queued and reserves 'synced' for server acknowledgement. Firestore Web persistence uses Android WebView IndexedDB, **not SQLite**. Test cold starts, login while offline, app restarts, airplane mode, reconnection, cache eviction, user switching, and server-side write rejection on physical Android devices.

## 5. Runtime integration and release gates

`src/lib/firebase.ts`, `src/services/firebaseAuth.ts`, `src/pages/SignInPage.tsx` and `src/pages/LessonViewer.tsx` are staged in the PR, but the current `src/App.tsx` still uses browser-local demo users, roles and guides. Do not route an untrusted demo identity into Firebase or claim zero content reads/live Firebase migration before the real master and authenticated UID mapping exist. Switch the app/router atomically after master, Web config, rules and identity migration have been checked; remove demo identity and old storage consumers and reconcile historical progress intentionally.

Run `npm ci`, `npm run build`, `npm run lint`, VOP regression tests and snapshot tests. Then configure and verify Android registration, run `npx cap sync android`, build an Android APK/AAB using the correct signing configuration and inspect package ID `com.sda.vop`. The new package ID is NOT an in-place update to existing `com.rvc.vopapp` installations; plan user migration/communication if they have live data. Verify real Email/Password, native Google, offline snapshots, a single submission, sync, and adversarial Firestore rules. Do not merge/deploy or issue official certificates until these release gates pass. Only an independently trusted grader and authorized approval service may produce official grades/certificates.
